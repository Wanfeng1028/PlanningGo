# 2026-06-07

## GitHub Security Report 修复 — 6 项安全加固

根据用户提供的 GitHub 安全分析报告（71 个漏洞），判断其中大量 CRITICAL/HIGH 为误报或夸大，优先修复了以下 6 个真问题：

1. **Agent 工具参数 Zod 校验** (`tools.ts`, `slotTools.ts`, `placeTools.ts`, `actionTools.ts`)
   - 之前：LLM 传入的工具参数只做 JSON.parse + `as Type` 转型，无任何 schema 校验
   - 修复：为 4 个工具各加 Zod schema，运行时校验后执行

2. **工具结果二次 Prompt Injection** (`agentRuntime.ts`, `placeTools.ts`)
   - 之前：工具原始结果直接回灌 LLM，高德 POI 的 message 字段等外部数据可影响模型推理
   - 修复：回灌前做长度截断（2000 字符）、控制字符清理；POI 结果仅暴露安全字段 allowlist

3. **`/api/agent/plans/select` BOLA** (`agentChat.ts`)
   - 之前：只检查 conversation 是否存在，不校验 userId/guestId 归属
   - 修复：引入 `assertConversationOwnership()` 统一校验（支持 DB + memory 模式）

4. **日志脱敏未覆盖所有落库路径** (`eventService.ts`, `developerRepository.ts`, `agentRuntime.ts`)
   - `eventService.ts` 已正确调用 `sanitizeForLog()`
   - `developerRepository.ts`：createRequestLog 的 requestPreview/responsePreview 现在经 sanitizeForLog
   - `developerRepository.ts`：recordDelivery 的 payload 现在经 sanitizeForLog
   - `agentRuntime.ts`：saveMsg 的 payloadJson 现在经 sanitizeForLog

5. **HandoffCode 短码安全加固** (`handoffCodeService.ts`, `handoff.ts`)
   - 码长从 6 位增加到 10 位（熵值 2^52 → 2^60）
   - getHandoffCode 不再返回 userId/guestId，减少信息泄露
   - handoff.ts 已有 code 限流（Redis 每 IP+code 每分钟 5 次）和 metadata-only 接口

6. **生产环境 mock/demo 路由保护** (`reservations.ts`, `execution.ts`)
   - mock.ts 已有生产跳过
   - reservations 所有路由在生产要求 auth
   - execution demo 接口在生产要求 auth

### 未被修复的（判断为误报/低风险）
- JWT/Cookie 默认密钥：生产有 validateProductionJwtSecrets() 拦截
- docker-compose.yml 数据库密码：生产用 docker-compose.prod.yml
- `/api/health` 暴露过多：现在只返回 ok/status/timestamp
- Sentry DSN 暴露：前端 DSN 本就公开，Replay 已开启 mask
- Memory 硬删除：账号删除时硬删是用户的删除权
- CI 测试密码：GitHub Actions service container 临时凭据
- `^` 依赖版本：CI/Docker 用 npm ci 锁定安装
