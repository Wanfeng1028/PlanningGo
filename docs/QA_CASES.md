# PlanningGo QA 用例表

> 最后更新：2026-06-02
> 负责人：AI-5（质量闸门）

## 核心用户路径

| 编号  | 场景                         | 输入                                  | 预期行为                 | 是否需要 LLM | 是否需要地图 | 通过标准                         |
| ----- | ---------------------------- | ------------------------------------- | ---------------------- | ------------ | ------------ | -------------------------------- |
| QA-01 | 基础问候                     | `你好`                                | 自然回复问候，不重复模板 | 否           | 否           | 1 秒内返回，无固定长模板          |
| QA-02 | 身份询问                     | `你是谁`                              | 简短身份说明            | 否           | 否           | 不出现"我是AI助手"等固定模板      |
| QA-03 | 雨天规划                     | `明天杭州下雨，和朋友吃饭逛逛，预算300` | 2-3 个方案，含雨天备选   | 是           | 可选         | 至少 1 个方案考虑雨天室内活动     |
| QA-04 | 适老规划                     | `周末带爸妈在上海半天，别太累`         | 适老、低强度方案        | 是           | 可选         | 有休息安排，风险提示合理          |
| QA-05 | 出发地+预算                  | `我在仓前，想去下沙附近吃饭，不想太贵`  | 利用出发地和预算约束    | 是           | 是           | 不跨城市，有价格区间              |
| QA-06 | 上下文修改                   | （接 QA-05）`把第二个方案改省钱`       | 基于上下文调整方案      | 是           | 否           | 不重新开聊，修改的是已有方案      |
| QA-07 | LLM key 错误                 | （配置错误 API key 后请求）            | 明确错误提示            | 否           | 否           | 不 fallback 成模板内容，错误可理解 |
| QA-08 | AMAP key 缺失                | （不配置 AMAP key，发规划请求）         | 降级提示或无地图方案    | 是           | 否           | 不崩溃，返回无地图版本            |
| QA-09 | 移动端输入                   | 375px 宽度下输入长文本                  | 输入栏不遮挡内容        | 否           | 否           | 输入框始终可见，键盘弹出不遮挡    |
| QA-10 | 生产 ready                   | `GET /api/ready`                       | 状态明确                | 否           | 否           | 不泄露 API key，返回 db/redis 状态 |
| QA-11 | SSE 流式响应                 | `POST /api/agent/chat/stream`          | 流式返回文本 + [DONE]   | 是           | 可选         | 最终收到 `[DONE]`，loading 清除   |
| QA-12 | 会话连续性                   | 连续发 3 条消息                        | 同一 conversationId     | 是           | 可选         | 第 3 条消息仍记住前两条上下文     |
| QA-13 | 方案选择                     | 生成方案后选择一个                     | 返回 plan_selected 类型 | 是           | 否           | nextActions 列表完整              |
| QA-14 | 异常输入                     | 发送空字符串或超长文本（>10000字）      | 返回 400 错误           | 否           | 否           | 不 500，错误信息可理解            |
| QA-15 | 并发限流                     | 1 分钟内发 >100 次请求                 | 返回 429               | 否           | 否           | Retry-After header 存在          |

## 测试环境要求

- **基础环境**：`npm run dev:full` 启动前后端
- **LLM 测试**：至少配置一个 LLM provider 的 API key
- **地图测试**：配置 `AMAP_WEB_SERVICE_KEY`
- **移动端测试**：Chrome DevTools 设备模拟 375px
- **生产测试**：`NODE_ENV=production` + 真实数据库 + Redis

## 执行方式

```bash
# 自动化 smoke 测试
npm run smoke:all

# 按上表输入 → 检查预期 → 记录结果
```
